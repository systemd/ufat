# Hacking on ufat

ufat is built with meson and plain rustc. There is no cargo build and
there are no external crates.

## Requirements

- rustc 1.85 or newer. ufat has to keep building with rustc 1.85.
- meson 1.4 or newer and ninja.
- rustfmt, for the formatting check.

## Building

    meson setup build
    meson compile -C build
    meson install -C build

`meson compile` builds the library `build/src/libufat.rlib`, the tool
`build/ufat` and the tests. `meson install` installs the tool into the
`bin` directory below the prefix, `/usr/local` by default.
`meson setup --prefix=` changes the prefix.

`RUSTC=` selects the compiler when the build directory is set up:

    RUSTC="rustup run 1.85.0 rustc" meson setup build-1.85

`meson setup -Dstatic=false` links `build/ufat` dynamically. By default
it is linked statically.

## Tests

    meson test -C build

`meson test` runs:

- the unit tests of the library and of the json and varlink crates,
- the integration tests in tests/,
- the crash consistency harness.

Set `TMPDIR` to a directory with a short path that is not a symbolic
link. Some tests create Unix sockets below it, and socket paths are
limited to 108 bytes. One test compares the targets of
/proc/self/fd with paths below `TMPDIR`.

`meson test` runs several test binaries at the same time. `-j 1` runs
one at a time. `RUST_TEST_THREADS=` limits how many tests of one binary
run at the same time.

tests/varlink.rs also drives the service with `varlinkctl` when it is
installed.

## Formatting

    meson compile -C build rustfmt
    meson test -C build --suite style

The code is formatted with rustfmt. rustfmt.toml sets the line width to
120 columns. The `rustfmt` target formats the code. The `style` test
suite checks the formatting. A plain `meson test` leaves it out.

## Lints

    meson compile -C build
    ninja -C build clippy

The `clippy` target runs clippy on every crate. Run it after the build.
In a build directory set up with `--werror`, every clippy warning fails
the target. clippy.toml sets the oldest rustc ufat builds with, so clippy
does not suggest functions that rustc 1.85 lacks. clippy reads
clippy.toml when the build directory is inside the source directory. For
a build directory elsewhere, set `CLIPPY_CONF_DIR` to the source
directory.

## The case folding table

src/name/fold_table.rs is generated by tools/fold-table.rs. It holds the
upper case mappings of Unicode 16.0.0, the version rustc 1.85 ships. The
generator refuses to run with a compiler that ships another version, so
use a build directory set up with rustc 1.85:

    RUSTC="rustup run 1.85.0 rustc" meson setup build-1.85
    meson compile -C build-1.85 update-fold-table
    meson compile -C build-1.85 check-fold-table

`update-fold-table` regenerates the table. `check-fold-table` compares
it with a fresh one. Moving to another Unicode version changes which
names ufat tells apart. Do it on purpose and in a commit of its own.

## Exhaustive sweeps

    meson configure build -Dslow-tests=true
    meson test -C build --suite slow

tests/exhaustive.rs checks the layout computation, the time conversion
and the name handling over large ranges of inputs. It takes about a
minute on 16 cores. It is built and run only when the `slow-tests`
option is set.

## Kani proofs

The pure modules contain proofs for the Kani model checker in
`#[cfg(kani)]` blocks. verify/lib.rs is a crate root that holds only
these modules. Install Kani with:

    cargo install --locked kani-verifier
    cargo kani setup

Then run:

    meson compile -C build verify
    HARNESS=layout::proofs::compute_fixed_params_any_total meson compile -C build verify
    SLOW=1 meson compile -C build verify
    DIR=1 meson compile -C build verify

`HARNESS=` runs one harness. `SLOW=1` adds the harnesses that take longer
than half an hour. `DIR=1` adds the harness of the directory index, which
has not finished yet.

Up to four harnesses run at the same time. `KANI_JOBS=` changes that.
`KANI_VERBOSE=1` runs them one after the other and prints every check.
Some harnesses need more memory than a laptop has. The default set takes
about half an hour on a 512 core machine with `KANI_JOBS=24`.

## Reference tests

tests/reference.rs compares ufat with mkfs.fat, fsck.fat, mtools and
sha256sum. A test whose tool is not installed is skipped.
`UFAT_MTOOLS=` points at a directory with mtools binaries, for example a
local build.

## Crash consistency

tests/crash.rs records the writes of a test scenario. It uses a copy of
the library built with `--cfg ufat_trace`. It then builds every state a
crash could leave on the device and checks each one with fsck and
against the expected files. Three models of the device are checked:

- Every sector is written whole, and writes land in order.
- A write of several sectors can stop at any sector boundary.
- Between two flushes, the device can keep any subset of the writes.

The harness runs as part of `meson test`. For its full output, run it
directly:

    build/tests/test-crash --nocapture --test-threads=1
    UFAT_CRASH_FULL=1 build/tests/test-crash --nocapture --test-threads=1

`UFAT_CRASH_FULL=1` checks every subset of the writes between two
flushes instead of a sample.

## Fuzzing

    meson compile -C build fuzz
    ITERATIONS=20000 WORKERS=16 meson compile -C build fuzz

The `fuzz` target mutates FAT images and manifests and runs the tool and
the service on them. It also sends malformed Varlink messages to the
service. The default run takes about 15 seconds. It needs python3.
mkfs.fat and mtools add more seed images when they are installed.

The results go to `build/fuzz`. `FUZZ_OUT=` changes that. Every crash,
hang or unexpected exit is stored under `out/findings` together with the
input that caused it. tests/fuzz/repro/ holds checks for defects found
earlier.

## Coverage

    meson setup -Db_coverage=true build-coverage
    meson test -C build-coverage
    meson compile -C build-coverage coverage-report

With `-Db_coverage=true` everything is built with coverage
instrumentation, and the tests leave their profiles in
`build-coverage/coverage`. The `coverage-report` target merges the
profiles of the test runs since the last report and prints the line
coverage of every file. The report is saved in
`build-coverage/coverage/report.txt`.

The report needs llvm-profdata and llvm-cov at least as new as the LLVM
in rustc. `LLVM_PROFDATA=` and `LLVM_COV=` select them. `meson setup`
warns that gcovr or lcov is missing. The `coverage-report` target needs
neither.

## Benchmarks

    meson compile -C build bench
    BENCH_CASES='^populate|^fsck' meson compile -C build bench

bench/run.sh generates an ESP of 270 MB and trees of 10000 files. It
times ufat against mkfs.fat, mcopy, fsck.fat and sha256sum on them, and
checks that `ufat assemble` and `mkfs.fat` write the same bytes.
`BENCH_CASES=` selects cases by a regular expression. The other settings
are described at the top of bench/run.sh. The results are in
`$BENCH_DIR/out/summary.txt`.

## Continuous integration

GitHub Actions runs .github/workflows/ci.yml for every pull request, for
every push to main and once a week. It runs:

- the build and the tests with rustc 1.85 and with the current stable
  rustc, on x86_64 and aarch64, with `--werror`,
- `check-fold-table` with rustc 1.85,
- rustfmt and clippy,
- the exhaustive sweeps,
- the fuzzing campaign, with 5000 iterations in the weekly run,
- the coverage report, which is shown in the job summary,
- Kani with `--only-codegen`, which checks that every proof builds. The
  proofs themselves need more time and memory than the CI has.

The build jobs fail when mkfs.fat, fsck.fat, mtools or a varlinkctl with
`--push-fd` is missing, instead of skipping the tests that need them.
