# Hacking on ufat

ufat is built with cargo. It depends on the libc, sha2 and lexopt
crates. lexopt parses the command line of the tool.

## Requirements

- rustc and cargo 1.85 or newer. ufat has to keep building with rustc
  1.85.
- Linux with glibc, on x86_64, i686, aarch64, armv7, loongarch64,
  powerpc, powerpc64, powerpc64le, riscv64, s390x or sparc64. The build
  fails on other targets, musl included.
- rustfmt, for the formatting check, and clippy, for the lints.

## Building

    cargo build --locked
    cargo build --release --locked

`cargo build` builds the library and the tool `target/debug/ufat`.
`--release` builds `target/release/ufat`. `cargo install --locked --path .`
installs the tool into `~/.cargo/bin`. With `--root /usr/local` it goes
into /usr/local/bin.

Cargo.lock is part of the tree. `--locked` makes cargo use the versions
it lists.

With rustup, `cargo +1.85.0` selects rustc 1.85:

    cargo +1.85.0 build --locked

## Tests

    cargo test --locked

`cargo test` runs:

- the unit tests of the library and of the json and varlink crates,
- the integration tests in tests/,
- the crash consistency harness.

The tests build with the dev profile, which is optimized and keeps the
overflow checks and debug assertions. `--release` turns those off.

Set `TMPDIR` to a directory with a short path that is not a symbolic
link. Some tests create Unix sockets below it, and socket paths are
limited to 108 bytes. One test compares the targets of
/proc/self/fd with paths below `TMPDIR`.

`cargo test` runs the test binaries one after the other.
`RUST_TEST_THREADS=` limits how many tests of one binary run at the
same time.

## Formatting

    cargo fmt --all
    cargo fmt --all --check
    rustfmt --check --edition 2021 verify/lib.rs

The code is formatted with rustfmt. rustfmt.toml sets the line width to
120 columns. `cargo fmt --all` formats the code, and `--check` checks
it. verify/lib.rs belongs to no package, so rustfmt checks it directly.

## Lints

    cargo clippy --locked --workspace --all-targets -- -D warnings

clippy checks every crate, the tests and the helpers included. It takes
the oldest rustc ufat builds with from `rust-version` in Cargo.toml, so
it does not suggest functions that rustc 1.85 lacks.

The lints depend on the target and on the version of rustc. `--target`
checks another architecture once `rustup target add` has installed it.
That needs no cross linker.

## The case folding table

src/name/fold_table.rs is generated by tools/fold-table.rs from
UnicodeData.txt and SpecialCasing.txt of Unicode 16.0.0.
tools/fold-table.sha256 holds their hashes. To check the table, download
the two files, check their hashes, and compare the generated table with
the one in the tree:

    mkdir ucd
    curl -sSfL -o ucd/UnicodeData.txt https://www.unicode.org/Public/16.0.0/ucd/UnicodeData.txt
    curl -sSfL -o ucd/SpecialCasing.txt https://www.unicode.org/Public/16.0.0/ucd/SpecialCasing.txt
    (cd ucd && sha256sum -c ../tools/fold-table.sha256)
    cargo run --locked -q -p fold-table ucd | diff -u src/name/fold_table.rs -

The table never changes. A newer Unicode version would make some names
that differ today one name.

## Exhaustive sweeps

    cargo test --locked --test exhaustive -- --ignored

tests/exhaustive.rs checks the layout computation, the time conversion
and the name handling over large ranges of inputs. It takes about a
minute on 16 cores. Its tests are ignored by default, so a plain
`cargo test` skips them.

## Kani proofs

The pure modules contain proofs for the Kani model checker in
`#[cfg(kani)]` blocks. verify/lib.rs is a crate root that holds only
these modules. Install Kani with:

    cargo install --locked kani-verifier
    cargo kani setup

Then run:

    verify/run.sh
    HARNESS=layout::proofs::compute_fixed_params_any_total verify/run.sh
    SLOW=1 verify/run.sh
    DIR=1 verify/run.sh

`HARNESS=` runs one harness. `SLOW=1` adds the harnesses that take longer
than half an hour. `DIR=1` adds the harness of the directory index, which
has not finished yet.

Up to four harnesses run at the same time. `KANI_JOBS=` changes that.
`KANI_VERBOSE=1` runs them one after the other and prints every check.
Some harnesses need more memory than a laptop has. The default set takes
about half an hour on a 512 core machine with `KANI_JOBS=24`.

## Reference tests

tests/reference.rs compares ufat with mkfs.fat, fsck.fat, mtools and
sha256sum. A test whose tool is not installed is skipped.
`UFAT_MTOOLS=` points at a directory with mtools binaries, for example a
local build.

## Crash consistency

tests/crash/crash.rs records the writes of a test scenario. It uses a
copy of the library built with `--cfg ufat_trace`, the ufat-trace
package. It then builds every state a crash could leave on the device
and checks each one with fsck and against the expected files. Three
models of the device are checked:

- Every sector is written whole, and writes land in order.
- A write of several sectors can stop at any sector boundary.
- Between two flushes, the device can keep any subset of the writes.

The harness runs as part of `cargo test`. For its full output, run it
on its own:

    cargo test --locked -p ufat-trace -- --nocapture
    UFAT_CRASH_FULL=1 cargo test --locked -p ufat-trace -- --nocapture

`UFAT_CRASH_FULL=1` checks every subset of the writes between two
flushes instead of a sample.
